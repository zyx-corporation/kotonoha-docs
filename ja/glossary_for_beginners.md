# 初学者向け用語集

この用語集は、Kotonoha を初めて読む人のための説明です。厳密な仕様定義ではありません。実装者向けの正本は [`kotonoha-spec`](https://github.com/zyx-corporation/kotonoha-spec) を参照してください。

## まず覚える用語

| 用語 | ざっくりした意味 | もう少し正確に言うと |
| --- | --- | --- |
| Kotonoha | 意味の変化を扱う仕組み | AI 支援開発や文書更新で、元の意図・制約・未解決点がどう変わったかを記録・確認するためのドキュメントとツール群 |
| SLS | 意味の履歴を残す考え方 | Semantic Lineage System。変更前後の意味の系列、由来、判断、レビュー結果を追跡するための枠組み |
| RDE | 意味のずれを見る点検票 | Resonant Deviation Evaluator。生成物や変更案が、元の議論・意図・価値・設計思想からどう変化したかを確認するレビュー構造 |
| semantic lineage | 意味の系譜 | ある成果物が、どの意図・議論・判断から生まれ、どのように変化してきたかという履歴 |
| ΔM | 意味変化 | 変更の前後で意味がどう変わったかを表す考え方。価値そのものではなく、価値判断の材料になる変化量 |

## CLI で出てくる用語

| 用語 | ざっくりした意味 | 初学者向けメモ |
| --- | --- | --- |
| CLI | コマンドで使う道具 | Command Line Interface。ターミナルから `kotonoha` コマンドとして使う |
| `kotonoha version` | バージョン確認 | どの CLI が、どの仕様 bundle を対象にしているかを見る入口 |
| RDE skeleton | RDE の最小ひな形 | 意味変化レビューを書くための空の点検票 |
| validate | 形の検証 | JSON などの出力が、期待される形に合っているかを確認する |
| strict | 厳密検証 | 余分なフィールドや未定義の形を許さない確認モード |
| interchange envelope | ツール間で渡す封筒 | Kotonoha 関連データを、CLI・UI・他ツール間で受け渡すための共通形式 |

## レビューで見る観点

RDE では、少なくとも次のような観点を見ます。

| 観点 | 意味 | 例 |
| --- | --- | --- |
| 保存された要素 | 元の意図や制約が残っている部分 | 「人間が最終判断する」という原則が残っている |
| 変換された要素 | 形や表現が変わった部分 | 議論を仕様文に変換した |
| 補完された要素 | 元の議論には明示されていなかったが、必要に応じて足した部分 | エラー処理や確認手順を追加した |
| 未解決の要素 | まだ決めきらずに残した部分 | UI 表示形式は後で検討する |
| 失われた要素 | 変更によって見えにくくなった部分 | 曖昧さや注意書きが要約で消えた |
| 逸脱リスク | 元の意図から危険にずれる可能性 | AI の評価を人間承認の代替に見せてしまう |
| 次回更新方針 | 次に直すべきこと | 初学者向け説明を追加する |

## よくある誤解

| 誤解 | 補足 |
| --- | --- |
| Kotonoha は Git の代替である | 代替ではありません。Git が文字列差分を残し、Kotonoha は意味変化を見る層を追加します。 |
| RDE は AI 出力の合否判定器である | 合否判定器ではありません。人間が判断するためのレビュー構造です。 |
| SLS を使えば意味が完全に保存される | 完全保存はできません。失われたものや未解決のものを見えやすくするための仕組みです。 |
| `validate --strict` が通れば意味的に正しい | strict 検証は形式の確認です。意味の判断は別に必要です。 |
| 仕様を全部読まないと使えない | 初学者はチュートリアルから始めれば十分です。厳密な適合性が必要になった段階で仕様を読みます。 |

## 読み替えの目安

初学者は、次のように読み替えると理解しやすくなります。

| 難しい言い方 | 最初の読み替え |
| --- | --- |
| Semantic Lineage System | 意味の履歴を残す仕組み |
| Resonant Deviation Evaluator | 意味のずれを確認する点検票 |
| interchange | ツール間で受け渡す封筒 |
| normative | 正本として従うべき仕様 |
| informative | 理解を助ける説明文書 |
| conformance | 実装が仕様に合っているか |
| acceptance demo | リリース確認用の動作チェック |

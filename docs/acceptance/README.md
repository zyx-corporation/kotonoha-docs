# Acceptance demos

Acceptance demos are procedural checks used to confirm that a public Kotonoha surface behaves as expected for a given phase.

They are **not tutorials**. They may look like walkthroughs, but their primary purpose is validation: commands, expected exit codes, expected outputs, and links to the canonical specification.

Use this section when you want to answer questions such as:

- Does the Phase 2 CLI minimum surface run successfully?
- Do validation commands return the expected exit codes?
- Does an optional persistence path work with the documented setup?
- Which public behavior is tied to an internal acceptance checklist?

For learning-oriented material, use [Tutorials](../tutorials/README.md).
